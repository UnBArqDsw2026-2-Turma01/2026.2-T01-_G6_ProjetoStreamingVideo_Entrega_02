# Evidências — Usuários e Canais

Esta página delimita as evidências usadas no componente de Usuários e Canais. As capturas permanecem na página [Evidências do Diagrama de Classes](1.1.1.1.1.Foco01.Evidencias.md).

## E1 — usuário e criador são papéis distintos

**Fonte:** documentação pública da operação de consulta de usuários da plataforma de referência.

**Implicação no UML:** `User` concentra a identidade básica; `CreatorProfile` é opcional e registra `isEligibleToStream`. A associação `User 1 — 0..1 CreatorProfile` evita transformar todo usuário em criador.

## E2 — canal é uma entidade própria

**Fonte:** documentação pública da operação de informações de canal.

**Implicação no UML:** `Channel` possui identidade, slug, título e estado público `isLive`, separado do perfil que o administra.

## Decisões de projeto declaradas

| Decisão | Justificativa | Limite |
| -- | -- | -- |
| Um `CreatorProfile` administra um `Channel` | Mantém o recorte compatível com a plataforma de referência | Múltiplos canais por criador não foram modelados |
| `User` solicita `ClipRequest` | Torna explícito o papel de `requestedByUserId` já presente no pedido | Não modela permissões de edição do clipe |
| `User` inicia `PlaybackSession` opcionalmente | Conecta a identidade ao consumo sem impedir espectador anônimo | A política real de acesso anônimo não foi observada |

## Matriz de revisão

| Evidência | Elementos revisados | Resultado |
| -- | -- | -- |
| E1 | `User`, `CreatorProfile`, `isEligibleToStream`, multiplicidade `0..1` | Papel opcional de criador representado |
| E2 | `Channel`, `slug`, `title`, `isLive` | Canal separado do perfil representado |
| Decisão de projeto | Ligações com `ClipRequest` e `PlaybackSession` | Integração entre componentes explicitada |
