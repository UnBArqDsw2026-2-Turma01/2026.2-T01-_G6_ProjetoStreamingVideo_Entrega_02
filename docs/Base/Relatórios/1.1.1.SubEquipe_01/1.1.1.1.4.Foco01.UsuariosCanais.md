## Elementos incorporados ao modelo

| Elemento | Responsabilidade | Evidência principal |
| -- | -- | -- |
| `User` | Identidade básica usada para autoria, solicitação de clipes e reprodução autenticada | E1 |
| `CreatorProfile` | Papel opcional que registra a elegibilidade para transmitir | E1 |
| `Channel` | Identidade pública do canal e indicação de transmissão ativa | E2 |

## Relações e multiplicidades

- Um `User` possui zero ou um `CreatorProfile`, pois nem todo usuário é criador.
- Cada `CreatorProfile` administra exatamente um `Channel` no recorte adotado.
- Um usuário pode solicitar vários `ClipRequest`; cada pedido identifica um solicitante.
- Um usuário pode iniciar várias `PlaybackSession`; a sessão admite usuário ausente para representar acesso anônimo.
- A autoria de `LiveStream` continua ligada ao usuário por meio das relações já existentes no modelo integrado.

## Decisões e limites

- Criador é um papel opcional, não uma subclasse de usuário. Isso permite que a mesma identidade produza e consuma conteúdo.
- A cardinalidade de um canal por perfil é uma decisão de simplificação do recorte. Plataformas que permitam múltiplos canais exigiriam revisão da multiplicidade.
- `isLive` representa o estado público do canal, mas a fonte de verdade do ciclo de vida continua sendo `LiveStream.status`.
- Autenticação, preferências pessoais e gerenciamento de credenciais permanecem fora deste componente.
